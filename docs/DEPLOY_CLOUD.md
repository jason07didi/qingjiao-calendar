# 青椒的日历 · 云端自动更新部署指南

## 为什么需要这步
本地演示模式（config.js 的 cloudEnv 为空）只会显示写死的静态数据，不会刷新。
要「每天定时像人一样爬取、云端自动更新、微信每日提醒收藏」，必须接微信云开发。

## 费用
- 微信云开发 **基础版 0 元/月、长期免费**（不是试用期）。
- 免费额度对小工具足够：云函数 20 万次/月、数据库读 5 万/天、写 3 万/天、存储 2GB。
- 你这个量级长期跑在免费线内，不会扣费。

## 步骤
1. **开通云开发**：微信开发者工具 → 顶部「云开发」→ 开通 → 选择「基础版（免费）」。
2. **复制环境 ID**：云开发控制台 → 设置 → 环境 ID（形如 prod-xxxxxxxx）。
   填进 `utils/config.js` 的 `cloudEnv: ''`（替换空字符串）。
3. **上传云函数**：在 `cloudfunctions/` 下，对 spider / notify / admin 三个目录分别
   右键 → 上传并部署（云端安装依赖）。
4. **上传触发器**：对 spider（00/06/12/18 点爬取）和 notify（每天 08:00 推送）
   右键目录 → 上传触发器（config.json 已配好）。
5. **初始化数据（首次）**：
   - 方式 A（推荐）：运行 `node tools/export_seed.js` 生成 `data/notices_seed.json`，
     在云开发控制台 → 数据库 → notices 集合 → 导入该 JSON。
   - 方式 B：云函数 admin → 测试，传 `{ "action": "import", "items": [...] }`（大数据量用方式 A）。
6. **建集合**：数据库里新建 4 个集合，权限都设「仅创建者可读写 / 所有用户可读」：
   - `notices`（通知主表）
   - `crawl_logs`（爬取/推送日志）
   - `subs`（用户收藏+订阅）
   - （收藏本地已有 `pc_favorites`，上云后同步进 subs）
7. **订阅消息（每日提醒收藏，可选但推荐）**：
   - 微信公众平台 → 订阅消息 → 申请「科研截止提醒」类模板，拿到模板 ID。
   - 填进 `utils/config.js` 的 `subscribeTmplId` 和云函数 notify 的 TMPL_ID（环境变量）。
   - 用户在小程序详情页点「提醒我」授权一次，notify 每天 08:00 给他推收藏的临近截止。

## 数据流
```
[官方政府/学会网站]
      │  spider 定时爬取（00/06/12/18）
      ▼
[云数据库 notices]  ──raw（待核实）──▶ admin audit ──▶ curated（前端可见）
      │                                          │
      │ 前端 getList 每 6h 缓存 + 下拉强制刷新      │
      ▼                                          │
[小程序列表/日历]                              [subs 收藏]
                                                  │ notify 每天 08:00
                                                  ▼
                                            [微信订阅消息：只推收藏]
```

## 现实约束（务必知悉）
- **爬取稳定性**：政府站点有反爬/WAF/TLS/改版风险，部分源可能爬不到。spider 会跳过失败源、
  记录到 crawl_logs，绝不清空已上线数据。部署后请在云开发日志逐个核对解析质量，
  对解析不干净的源在 sources.js 加白名单或正则。
- **截止日铁律**：爬取到的「日期」多为发布日，不等于截止日。spider 全部标
  deadlineEstimated=true 并进入 raw 待核实；只有经人工/审核确认或明确写「截止」的才转 curated。
  绝不编造精确截止日。
- **订阅消息限制**：默认「一次性订阅」（用户点一次授权推一次）。想「每天固定推」需申请
  长期订阅资质（难，一般仅政务/医疗）。这是微信平台规则，非代码可绕过。
