# 让数据每天自动更新：三条路，和为什么必须先开通云开发

## 一句硬规则（所有方案的共同前提）

小程序**正式版**的 `wx.request` 只能请求在公众平台后台配置过、并且**已 ICP 备案**的域名。
`github.com`、`raw.githubusercontent.com`、`cdn.jsdelivr.net`、`*.github.io` 都不可能备案，
所以**小程序不能直接读 GitHub**，不管仓库建得多简单。

唯一不受这条限制的联网出口是微信自家的：
- `wx.cloud.callFunction` —— 调自己的云函数
- `wx.cloud.database` —— 读自己的云数据库

**结论：想自动更新，必须开通云开发。** 这不是选型偏好，是绕不过去的一步。

---

## 三条路，都能做到自动更新

| | 抓取在哪跑 | 数据存在哪 | 小程序怎么读 | 要不要腾讯云密钥 | 前端要不要改 |
|---|---|---|---|---|---|
| **A（最短，推荐）** | 云函数 `spider` 定时器，每天 0/6/12/18 点 | 云数据库 `notices` | `wx.cloud.database()` | 不需要 | **不用改** |
| **B（你要的形态）** | GitHub Actions 每天 07:30 | GitHub 仓库里的 JSON | 云函数当代理去拉 | 不需要 | 要加一层代理 |
| **C（GitHub 直写库）** | GitHub Actions 每天 07:30 | 云数据库 `notices` | `wx.cloud.database()` | 需要 SecretId/SecretKey | **不用改** |

三条路都卡在同一个前提：**云开发得先开通**。

- **A** 的代码已经在仓库里写好了：`cloudfunctions/spider/`（含定时器配置）+ `utils/api.js`（读库）。开通云开发、部署一次，就自动跑了。
- **B** 最贴近"建个仓库只提供数据"的想法，但小程序读不到 GitHub，必须让云函数去拉，等于多一跳、还依赖 GitHub 在腾讯云机房的可达性。
- **C** 已经写好 `scripts/push_to_cloud.js`，配三个密钥就能把数据推进库，但要去腾讯云控制台生成 API 密钥。

**建议走 A。** GitHub 仓库继续当代码仓库和备份，抓取交给云函数——同一朵云内部通信，不跨网、不超时、不需要任何密钥。

## 开通 + 上线的完整清单

### 1. 开通云开发（你在开发者工具里点，约 2 分钟）

微信开发者工具打开项目 → 顶部工具栏「云开发」→ 开通 → 选基础套餐。

记下**环境 ID**，形如 `prod-8g2abcde12345678`（云开发控制台 → 设置 → 环境 ID）。

> 云开发是付费能力，最低档按月计费。开通前请确认你能接受这笔固定支出。

### 2. 填环境 ID（改一行）

`utils/config.js`：

```js
cloudEnv: 'prod-8g2abcde12345678',   // ← 换成你的环境 ID
```

改完这一行，`utils/api.js` 的 `initCloud()` 就会生效，全站自动从「本地数据」切到「云端数据」。
**其余前端代码一行都不用动。**

### 3. 建集合

云开发控制台 → 数据库 → 新建集合 `notices`
权限选：**所有用户可读，仅管理端可写**

> 前端只读，写入全部由云函数（管理端权限）完成，所以选这个最安全。

### 4. 导入现有 305 条

`data/seed_notices.jsonl` 已经生成好了（305 行，curated 232 + raw 73）。

控制台 → 数据库 → `notices` → 导入 → 选该文件，冲突处理选「插入」。

> 这个文件由 `node tools/gen_seed.js` 生成，数据就是当前小程序里的 245 条人工整理 + 60 条自动抓取。
> 导完这一次就不用再导了，之后靠云函数增量更新。

### 5. 部署云函数

云开发控制台 → 云函数 → 依次部署：

| 函数 | 作用 | 注意 |
|---|---|---|
| `spider` | 抓官方列表页写库 | **超时时间改成 60 秒**（默认 3 秒会直接超时） |
| `admin` | 后台维护/导入 | 默认即可 |
| `notify` | 订阅消息推送 | 需先申请模板 ID，见下文 |

在开发者工具里对 `cloudfunctions/spider` 右键 →「上传并部署：云端安装依赖」。

### 6. 验证

1. 云开发控制台 → 云函数 → `spider` → 云端测试 → 运行一次，看返回的 `added/updated`。
2. 数据库 → `notices` → 条数应该从 305 往上涨。
3. 小程序里下拉刷新 → 首页「整理于」应显示真实拉取时间（精确到分钟），不再是「本地数据」。

## 订阅消息（真·微信推送）

`utils/config.js` 的 `subscribeTmplId` 现在是空的，点「提醒我」只会本地收藏，不会发通知。

要真推送：
1. 公众平台 → 订阅消息 → 选用「申报截止提醒」类模板 → 拿模板 ID
2. 填进 `utils/config.js` 的 `subscribeTmplId`
3. `cloudfunctions/notify/index.js` 里的 `TEMPLATE_ID` 改成同一个
4. 部署 `notify`，配一个每天 08:00 的定时触发器，扫 3 天内到期的收藏并推送

> 订阅消息是**一次性授权**：用户点一次「提醒我」，只能收到一条。想持续提醒必须每次重新授权，这是平台规则，不是实现问题。

## 常见坑

| 现象 | 原因 |
|---|---|
| 改了 `cloudEnv` 但首页还是老数据 | `utils/api.js` 有 6 小时本地缓存（`CFG.cacheTTL`），下拉刷新可强制拉取 |
| 云端条数一直是 0 | `notices` 里的 `status` 必须是 `curated` 或 `raw`，其它值会被 `fetchCloudList` 过滤掉 |
| `spider` 云函数报超时 | 云函数超时默认 3 秒，抓 8 个源不够，改 60 秒 |
| 收藏的条目在切云端后消失 | 本地 id 是裸 id（`3`），云端是 `c_jq_3`，收藏 key 变了。需要一次 id 迁移，见 `utils/store.js` |
| 上传报包体超限 | `data/` `tools/` `scripts/` `cloudfunctions/` 已在 `project.config.json` 的 packOptions.ignore 里排除 |
